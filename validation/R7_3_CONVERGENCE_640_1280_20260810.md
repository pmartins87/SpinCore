### What the 640 x4 runs establish

The three x4 candidates eliminate neural-fit failure as an explanation: every final Advantage and AveragePolicy fit passed. Exact per-seed audits were:

- separated Advantage x4: seed29 `Adv=0.510782`, `Policy=0.103934`; seed07 `0.510080 / 0.104840`;
- separated both x4: seed29 `0.510782 / 0.100522`; seed07 `0.510080 / 0.109814`;
- coupled Advantage x4: seed29 `0.507985 / 0.101409`; seed07 `0.501452 / 0.108370`.

The coupled x4 run has the best mean, but relative to corrected 640 it improves mean only about `5.6%`; p95 improves only about `1.0%`. Relative to strong-Advantage 640, its mean is only about `2.9%` better while p95 is actually worse. `both_x4` consumes much more strategy collection/training and gives no tail benefit.

Therefore the large x4 benefit seen in the short two-iteration screen is **not stable across five CFR iterations at acceptance scale**. Plain independent replication is a real variance reducer but not the missing convergence mechanism by itself. x8/x16 is not promoted: the exact Advantage oracle already showed diminishing returns from four to eight independent paths and p95 remained saturated at `1.0`.

## Active upper-bound and correlated-path tests

### Full-exact opponent upper bound — `31412933368`

A bounded 64-root/seed run compares the authoritative baseline with effectively complete opponent-action expectation (`exact level 128`, above the observed tree depth). This answers whether removing opponent sampling variance entirely can substantially stabilize fitted policies. It is an oracle/upper-bound test, not a production proposal.

### Common-random-number Advantage paths — `31413103901`

The 256-root screen compares `independent_1`, `independent_4`, `common_1`, and `common_4`. Common modes derive opponent-action randomness from iteration/root/traverser/replicate counters rather than algorithm seed. Under iteration-1 uniform behavior and shared decks, the two seeds must create byte-identical Advantage memories; the run fails if that invariant is violated.

This tests a different mechanism than merely adding samples: **correlating the stochastic estimator noise across runs so small early random differences are less able to amplify through regret matching in later CFR iterations**.

## Decision boundary

R7.3 remains **FAIL / ACTIVE**. R7.4 and R8–R12 remain blocked.

- If common random numbers work, promote a counter-based/common-path estimator to acceptance scale and then version/recertify checkpoint semantics.
- If partial/full expectation works better, promote the cheapest bounded enumeration level that captures most of the gain.
- If even full opponent expectation leaves large instability, external-sampling noise is not sufficient to explain the failure; the next target becomes iteration-level regret-sign sensitivity, policy-support discontinuity, neural target aggregation and control variates.
- Raw unique-root scaling and x8/x16 independent replication stay paused.
